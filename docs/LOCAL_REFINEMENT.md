# APIキー不要の文章補完

HS Voiceの「設定 → AI整形 → 入力前にAIで文章を仕上げる」をオンにすると、Apple Intelligenceで文字起こしを整えます。macOS 26以降の対応MacでApple Intelligenceのモデルが利用可能なことが必要です。初期設定と既存のオン／オフ設定は変更していません。

## 今回の変更

- 8文字未満の発言もAI整形の対象にします。
- 言いよどみ・言い直しの除去と、依頼／約束／報告、主体、否定、推測、名前、数字、期限の保持を指示します。
- 一律のビジネス調や番号付き箇条書きをやめ、話者の口調とカスタム指示を参考にします。
- 既に取得している入力先のアプリ名をAIに渡します。周囲の文書や画面内容は読みません。ブラウザ名だけではサイトや入力欄の用途までは分かりません。
- AI処理中の表示と、整形済み／変更なし／原文使用の結果をメニューと設定に表示します。
- AI処理中はEscでキャンセルできます。タイムアウト時はモデルにキャンセルを要求し、呼び出し元は30秒で原文に戻ります。キャンセルに協調しないモデル処理そのものを強制停止する保証はありません。

文章補完は端末内で行い、外部AIへの通信やAPIキーの登録は追加していません。音声認識の既存のAppleサービス接続条件は変えていないため、アプリ全体の完全オフライン動作を保証する意味ではありません。

## 長い入力

本文は4,000 UTF-8バイト、カスタム指示は900バイトを上限とし、超過時は切り捨てず原文を使用します。900バイトは日本語でおおむね300文字です。辞書とアプリ名は補助情報として量を制限しています。これらはトークン数を完全に保証する制限ではなく、モデル側の文脈超過も原文使用として通知します。

## 検証と限界

合成した日本語の15例を、変更前のサービスと最終プロンプトで端末内評価しました。最初の7例は調整にも使用し、続く5例の傾向を見て一度調整した後、新しい3例を追加しました。大規模な品質ベンチマークやTypelessとの直接比較ではありません。

このMac（macOS 26.5）では最終版15例のAI処理が約0.4〜0.9秒で完了しました。録音時間、音声認識、他アプリへの入力時間は含みません。短文整形と依頼の意図保持には改善が見られましたが、複雑な日時の言い直しや節の組み替えを原文のまま返す例が残っています。出力内容の正しさを保証するものではありません。

評価結果は `output/refinement-quality/` に保存しています。通常のテストではモデルを呼ばず、模擬バックエンドで短文・失敗・上限・キャンセル・タイムアウト等を確認します。

## 再現

```bash
xcrun swift test --disable-sandbox
scripts/refinement-evaluation.sh current
HSVOICE_REFINEMENT_EVALUATION_SUITE=heldout scripts/refinement-evaluation.sh current-heldout
HSVOICE_REFINEMENT_EVALUATION_SUITE=final scripts/refinement-evaluation.sh current-final
VERSION=1.7.2 BUILD_NUMBER=24 APP_SIGNING_IDENTITY=- INSTALLER_SIGNING_IDENTITY='' NOTARY_PROFILE='' ./scripts/build-installer.sh
```

インストーラは `release/HSVoice-1.7.2/HSVoice-Installer-1.7.2.pkg` です。[ダウンロードページ](https://kaiamucun.github.io/hsvoice/)から配布します。アプリはad-hoc署名、インストーラは未署名です。

## 外部AIオプション

Typelessは[公式Data Controls](https://www.typeless.com/data-controls)でクラウド処理とOpenAI等の外部LLM事業者の利用を説明しています。具体的な使用モデルや高速化の構成は同ページでは公開していません。

将来さらに補完力が必要になった場合は、端末内処理を維持したまま、任意のAPIキーで外部AIを選択できる拡張が考えられます。キーの安全な保存、送信範囲の表示、利用料金と遅延、失敗時の動作を含めて実装する必要があります。この変更では、利用者の希望に合わせてAPIなしの改善を先に行いました。
